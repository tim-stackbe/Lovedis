# Anti-Halluzinations-Regeln (NON-NEGOTIABLE)

1. **Keine erfundenen Fakten.** Jede Behauptung über Startup, Partner, Use Case, Kunde oder Relevanz braucht eine **Quellenangabe** im Format:  
   `[Quelle: <Dokument/Tab/Zelle/Notion-Seite>, Confidence: Hoch|Mittel|Niedrig]`

2. **Confidence-Skala:**
   - **Hoch:** Direkt aus Matrix, Workshop-Protokoll, Pitch-Transkript, verifiziertem CRM/Notion
   - **Mittel:** Aus Team-Notizen, indirekter Ableitung aus öffentlichem Startup-Profil
   - **Niedrig:** Hypothese — **muss** als offene Frage formuliert werden, nie als Fakt

3. **Gap-Flags:** Fehlende Informationen explizit markieren:  
   `[DATENLÜCKE: <was fehlt> — Empfehlung: <wie klären>]`

4. **Keine internen Scores an Partner.** LOVEDIS-Gesamtscores, Pipeline-Stufen und interne Verdikte **nicht** in Partner-slides. Nur kuratierte Einordnung + begründete Fit-Einschätzung.

5. **Keine erfundenen Partner-Zitate.** Wenn kein Zitat vorliegt: „Partner-Feedback ausstehend“ statt fiktiver Aussage.

6. **Startup-Größe/Reife:** Nur nennen, wenn belegt (z. B. „noch klein, wenig Kunden, Teilzeit“ nur mit Notiz-Quelle).

7. **Konflikt-Transparenz:** Wenn Startup bei Partner A Hoch/Hoch, bei Partner B Niedrig/Niedrig — **beide** darstellen, nicht mitteln.

8. **Use-Case-Spezifität:** „Sparring möglich, Use Case vordefinieren“ ist **kein** validierter Use Case — als **Klärbedarf** kennzeichnen.

# Evaluations-Methodik (3 Ebenen)

## Ebene 1 — Themenblock-Fit (strategisch)

Für jeden Partner und jedes Startup:

| Kriterium | Bewertung | Leitfrage |
|-----------|-----------|-----------|
| Block-Zuordnung | Primär / Sekundär / Kein Fit | In welchem der 4 Blöcke liegt der Kernnutzen? |
| Challenge-Fit | Passend / Teilweise / Kein Fit | Trifft die Lösung eine **konkrete** Partner-Challenge? |
| Horizont | Prozess / Produkt / Beides | Entspricht das der Partner-Innovationsstrategie? |
| Skalierbarkeit über Partner | Ein Partner / Mehrere / Branchenweit | Lohnt sich Scouting-Aufwand programmweit? |

## Ebene 2 — Match-Matrix (operativ)

Nutze das LOVEDIS-Matrix-Schema (Construction-Referenz + Industry analog):

| Feld | Werte | Entscheidungslogik |
|------|-------|-------------------|
| **S-Relevanz** (Startup→Partner) | Hoch / Mittel / Niedrig | Will das Startup mit diesem Partner arbeiten? |
| **P-Relevanz** (Partner→Startup) | Hoch / Mittel / Niedrig | Sieht der Partner echten Nutzen? |
| **Top-Match** | Ja/Nein | **Nur wenn S=Hoch UND P=Hoch** |
| **Use-Case-Typ** | Pilot, Co-Dev, Kundenbeziehung, White-label, Tech-Lizenz, Sparring | Art der Zusammenarbeit |
| **Use-Case-Konkretisierung** | Freitext | Muss Pain → Lösung → Ergebnis benennen |
| **Kontaktstatus** | None → In Kontakt → Folgetermin → Pilot vereinbart | Wo steht die Beziehung? |

**Priorisierungs-Matrix (für Empfehlungs-Slide):**

```
                    P-Relevanz
                 Niedrig    Mittel     Hoch
S-Relevanz Hoch    Klären    Nachfassen  TOP-Priorität
           Mittel   Parken    Beobachten  Partner aktivieren
           Niedrig  Stoppen   Stoppen     Startup aktivieren
```

## Ebene 3 — LOVEDIS Deep Scoring (intern, optional)

Nur zur internen Priorisierung — **nicht** in Partner-Version:

| Dimension | Gewicht | Gate |
|-----------|---------|------|
| Challenge Fit | 30% | **Hard Gate:** < 3/5 → „Kein Fit (Gate)" |
| Reife & Machbarkeit | 20% | |
| Team & Umsetzung | 15% | |
| Marktpotenzial & Skalierbarkeit | 15% | |
| Strategischer Ökosystem-Fit | 10% | |
| Traktion & Referenzen | 10% | |

**Empfehlungs-Bänder (intern):** ≥4.0 Klares Ja · 3.0–3.9 Ja mit Nachfassen · 2.0–2.9 Eher Nein · <2.0 Klares Nein

# Anti-Patterns (explizit vermeiden)

| ❌ Anti-Pattern | ✅ Stattdessen |
|----------------|----------------|
| Startup-Liste ohne Partner-Bezug | Need-to-Solution-Mapping je Partner |
| Technologie-Features statt Use Cases | „Pain → Lösung → messbares Ergebnis" |
| Alle Startups „spannend" nennen | Klare Tier-Einstufung mit Begründung |
| Einseitige LOVEDIS-Meinung | „Unsere Einschätzung" + explizite Partner-Frage |
| Vage „Sparring möglich" ohne Klärung | Als Klärbedarf markieren + konkrete Frage formulieren |
| 4 Blöcke nur als Agenda | Querverbindungen + Challenge-Einbettung zeigen |
| Baseline wiederholen ohne Mehrwert | Matrix, Blind Spots, Entscheidungslogik ergänzen |
| Halluzinierte Kunden/Referenzen | Nur belegte Traktion; sonst Gap-Flag |
| Textwüsten auf Slides | Max. 5 Bullets, 1 Kernaussage, visuelle Matrix |
| Fehlende Konflikt-Darstellung | Widersprüchliche S/P-Werte transparent zeigen |
